Working Circuit

A breadboard circuit that is wired correctly and runs the code you wrote. The ESP32 kit, the sensors, and MicroPython — checked against the class's own wiring reference rather than a photograph.

Not available yet 4 tasks planned Signed off by a TA
This track is not open yet. The tasks below are what it will contain, written down so the shape of it is clear. The videos have not been recorded and the checks have not been built, so nothing here can be submitted or signed off.

Why this track

Week 5 is where students first wire the kit, and the failure that costs the most time is a wiring mistake that looks fine in a photo. This repo already knows what correct wiring looks like — skills/maker/circuits/ holds 25 machine-readable circuits with real pin references — so a student's pin map can be checked against it instead of eyeballed.

What it will contain

Planned

Light an LED from a pin

(to record) the board, the breadboard, one resistor, one LED

Evidence: blink.py plus the pin you used

Would check: the pin exists on the board and is an output; the circuit matches circuits/led.yml

Planned

Read a button or a sensor

(to record) inputs, pull-ups, why a floating pin misbehaves

Evidence: the script plus the pin map

Would check: the pin can read; no output-only pin used as an input; imports resolve

Planned

Drive a servo or a motor

(to record) PWM, and why a motor never wires straight to a pin

Evidence: the script and the wiring map

Would check: the driver path matches circuits/motor-driver.yml or servo.yml; no actuator on a bare pin

Planned

Build a circuit of your own

(to record) from the prompt to a working circuit, the class's AI-assisted flow

Evidence: the script, the pin map, and a photo of the build

Would check: every pin valid and used once; the script compiles; the photo shows the build (a person)

Then: Power it up

Plug in and run your circuit with a TA present. Code and pin maps can be checked offline; that it actually lights up cannot.

What it needs first

The pin data is the real work. boards/*.yml lists pin *positions* but nothing electrical: there is no record of which pins are input-only, which are strapping pins that misbehave at boot, or which are the two the camera uses. Adding that metadata is required for these checks — and it improves the wiring-diagram skill students already use, so it is worth doing once.
