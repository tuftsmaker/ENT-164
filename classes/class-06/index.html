Connectivity options

Direct through the board's own hotspot, or shared over a network you both join.

Direct · the board's hotspot

The ESP32 creates its own WiFi network. Your phone joins it and opens the page at the board's own address — no router, no setup. While connected, your phone is off the internet.

Shared · through the internet

The board joins a network you and your phone already share. It gets an address on it, any device there can open the page — and the board can reach online services too.

Client and server

Two pieces make the system work: the board that serves the page, and the browser you control it from — connected directly, over the board's own WiFi.

Client, your phone asks for the page. Server, the board answers. No router, no cloud — the board is the whole network.

Change a color from your phone

An in-class exercise before the robot: one RGB LED, served as a page your phone opens.

The prompt

No programming required. Describe the project and let AI write the MicroPython: “I’ve connected an ESP32. I want to use MicroPython to control an RGB LED from my phone over a wireless hotspot.”

The board & language

ESP32 WROVER, MicroPython.

The component

RGB LED (common anode) and a 220 Ω resistor.

The goal

Change the LED's color from your phone's browser.

The connection

The board's own WiFi hotspot — your phone joins directly.

How it works

Every tap on your phone becomes a request the ESP32 answers.

1

A web server starts

Your ESP32 runs a web server that renders a web page. No separate computer needed.

2

The page gets an address

The board serves the page from the network it creates — the address the code prints, like http://192.168.4.1.

3

Your phone renders it

Your phone's browser renders the HTML that the ESP32's web server generates.

4

Requests round-trip

Interacting with the page sends a request to the ESP32 (its address is http://192.168.4.1). It reads the request, sets the pins, and answers with the next state.
