Purpose. Partner with opencode to design, wire, and build a working electronics project on your ESP32 kit. You bring the ideas; opencode writes the code, draws the wiring, and runs it on the board.

Before You Begin

  • Your electronics kit. Use the Freenove ESP32 starter kit handed out in class. Reach out to the instruction team if anything is missing.
  • opencode, set up and signed in. The app connected to the class workspace, with the class skills added. The setup guide walks through it once.
  • MicroPython on your board. Ask opencode, for example: "Install MicroPython on my ESP32 and make the internal LED blink." It puts MicroPython on the board over USB, then writes and runs your code on it. No separate IDE, no manual uploads.

Project Requirements

Technical

  1. At least one input device (sensor, button, potentiometer, etc.)
  2. The ESP32-WROVER microcontroller for processing
  3. At least one output device (LED, display, motor, buzzer, etc.)
  4. MicroPython code, generated with opencode and tested until it works

Process

  • Keep one continuous conversation with opencode, start to finish
  • Ask for a wiring diagram and wire from it — the class skill draws it with every wire clickable
  • Iterate at least twice: describe what happened, share the error text, refine

The AI-Assisted Making Process

Step 1: Brainstorm with opencode

Not sure what to build? Ask opencode to help you brainstorm.

Download the parts list image from the Canvas module, attach it to your first message, and use this prompt:

I'm a student working on an electronics project using MicroPython on an ESP32-WROVER microcontroller.

Based on the components available in the attached parts list, can you suggest 5-10 fun, creative, or interesting project ideas that I could build in one week?

I'm looking for projects that:
- Use at least one input (sensor, button, etc.)
- Use at least one output (LED, display, motor, etc.)
- Are beginner-friendly
- Could be fun, silly, useful, or cool to build

For each idea, briefly explain what it would do and which components I'd need.

Pro tip: Look through the suggestions and pick something that excites you. You can also tell opencode about your interests (music, games, art, etc.) and ask for ideas related to those.

Step 2: Continue the same chat for wiring and code

IMPORTANT: Keep using the same conversation. opencode remembers the parts list and your chosen project.

In the same chat, continue with:

I want to build [the project idea you chose]. Can you tell me:
1. How to wire these components to the ESP32 (which pins to use)
2. MicroPython code to make it work
3. Include comments explaining what the code does

Pro tip: Because you're continuing the same conversation, opencode already knows what components you have and can give you better, more specific help. Ask for the wiring as a diagram — the class skill draws every wire so you can follow it on the bench.

Step 3: Wire it up

  • Follow the diagram and connect components to the GPIO pins opencode recommends (the pin numbers are written on the board)
  • Double-check your connections before powering on
  • Take a photo of your wiring for your documentation

Step 4: Test and iterate in the same chat

Keep the conversation going. When something doesn't work:

  1. In the same chat, describe the problem: "The LED doesn't turn on" or "I get an error message that says..."
  2. Share the error text exactly as it appears
  3. opencode remembers your project and helps you fix it
  4. Test the new version

Pro tip: The more you tell opencode about what you see on the bench, the better its next suggestion gets.

Note: You are NOT graded on your coding skills. You're graded on your ability to collaborate with opencode, iterate, and learn from the process.

Prompting Tips for Success

DO:

  • Keep everything in one chat: opencode remembers your parts, your project, and your previous questions
  • Attach the parts list image at the start: let opencode see what you have available
  • Describe what you want clearly: "I want the LED to change colors based on distance"
  • Share error messages completely: copy the entire error text into the chat
  • Ask for explanations: "Can you explain what this line does in simple terms?"
  • Request step-by-step help: "Break this down into smaller steps"

DON'T:

  • Start a new chat for each question (you'll lose all the context)
  • Type out all the component names by hand (attach the image)
  • Say "make it work" without explaining what's wrong
  • Skip testing between iterations
  • Be afraid to ask "dumb" questions. opencode doesn't judge.
  • Give up after the first try. Iteration is the key.

Example complete conversation flow

You: [Attaches the parts list image] "I'm a student working on an electronics project. Based on these components, can you suggest some fun project ideas? I'm interested in music and interactive things."

opencode: [Provides 5-10 project suggestions]

You: "I love the idea about the distance-based color changer. Can you tell me how to wire the ultrasonic sensor and RGB LED to the ESP32, and give me the MicroPython code?"

opencode: [Draws the wiring diagram and writes the code]

You: "I wired it up like you said and ran the code, but the LED stays off. I checked my wiring twice. What could be wrong?"

opencode: [Provides debugging suggestions — remembers your project and wiring]

You: "That worked. Now can you modify the code so the red LED blinks when something is super close instead of staying solid?"

opencode: [Provides updated code — remembers everything from earlier]

Note: All of this happens in ONE continuous conversation.
