Connecting to an ESP32

Two ways to connect

Both work. Only one of them skips app development entirely.

Bluetooth

Short-range, device to device

Low-power, short-range communication. Like connecting to a phone app. Requires a native mobile app for user interaction.

This is hard. You'd have to build and ship an app.

WiFi

Internet-connected, browser-first

Internet access, higher data rates, and integration with cloud services. Users interact through a simple web browser interface. No app development needed.

Today's approach. The browser is your user interface.

WiFi connectivity

Client and server

Your phone asks for the page; the board serves it — over the board’s own WiFi. No router, no cloud.

Client — your phone asks  ·  Server — the board answers  ·  No cloud — the board is the whole network.

The prompt

“I want to change the color of an RGB LED from my phone. It sits on my breadboard: common anode to 3V3, R on GPIO 4, G on GPIO 2, B on GPIO 15. Create a WiFi hotspot on my ESP32 and serve a page with color buttons and sliders — I tap a color, the LED changes.”

The build

Wiring the drive train

The L298N sits between your ESP32 and the motors — the same wiring your robot already has.

The drive pins

ENA → GPIO 13  ·  ENB → GPIO 5
IN1 → GPIO 12  ·  IN2 → GPIO 14
IN3 → GPIO 18  ·  IN4 → GPIO 19
OUT1/2 → left motor  ·  OUT3/4 → right
12V ← battery pack  ·  shared GND

Wheels off the ground while you test. The motors spin the moment the code runs.

Build it up · step 1 of 4

Start with one button and one servo

The smallest piece of the robot: press, and the arm moves. Prove the loop before adding motors.

The prompt

“The servo and the joystick’s push button are wired to my ESP32: SW is GPIO 4 and the servo signal is GPIO 15. Make the button open and close the servo — one press opens it, the next press closes it. Write the MicroPython and tell me what I should see when I test it.”

One small ask, one test. This is the loop for every step after it.

Build it up · step 2 of 4

The stick drives

Now the drive train: forward and back, and pivoting turns with differential steering.

The prompt

“Now drive the robot from the joystick: up and down go forward and back, left and right pivot it with differential steering — the two motors spin opposite ways. The motors run through the L298N on GPIO 13, 12, 14, 18, 19 and 5; the stick’s VRx is GPIO 36 and VRy is GPIO 39. Stop when the stick is centered.”

This is the drive half of the robot — everything from step 1 stays wired.

Build it up · step 3 of 4

Check it before you trust it

Wheels off the ground first, then every direction on the floor.

The prompt

“Before we add WiFi, verify the robot moves correctly: add a self-test that drives forward, then backwards, then turns left and right — about a second each — and prints each step, so I can watch and check.”

Something off? Say exactly what you saw — “the left wheel spins backwards when I push up” — then re-test. One fix at a time.

On your phone

Every move is a request

The page has two controls: the stick drives, the button works the servo.

What each control does

Drag the stick → the motors follow your thumb
Let go → everything stops
Press the button → the servo opens or closes

Every drag and press is a request the board answers itself. The whole app is one page — nothing to install.

Under the hood

What happened?

Every tap on your phone becomes a request the ESP32 answers.

1

A web server starts

Your ESP32 runs a web server that renders a web page. No separate computer needed.

2

The page gets an address

The board serves the page from the network it creates — the address the code prints, like http://192.168.4.1.

3

Your phone renders it

Your phone's browser renders the HTML that the ESP32's web server generates.

4

Requests round-trip

Interacting with the page sends a request to the ESP32 (its address is http://192.168.4.1). It reads the request, sets the pins, and answers with the next page state.
