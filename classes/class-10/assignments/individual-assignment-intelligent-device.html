Overview

Use Claude to generate MicroPython code that connects your ESP32-WROVER to Claude's API and wires it into something physical. A sensor feeding data to Claude, a display showing Claude's response, a button triggering a prompt, or some combination. The code comes from Claude. The physical build and the prompting strategy come from you.

The Task

Build something physical that sends real-world data to Claude, displays Claude's response in the physical world, or both. Your project must include:

  1. A working API connection. Your ESP32 sends a prompt to Claude's API over WiFi and receives a response.
  2. Physical input, output, or both. At least one side of the interaction must go beyond the console and leverage a sensor or actuator.

Use Claude to generate all the code. Tell it you're using MicroPython on an ESP32-WROVER, what hardware you're wiring up (sensor model, display type, anything else in your kit), and give it the API key. Test in stages: get the API call working first, then the hardware, then combine them.

Your class API key is posted with this assignment in Canvas. Copy it from there, and do not share it outside class.

What to Submit

Prompt Log: Your full conversation with Claude showing your initial prompt, what broke, how you described problems back, and how many rounds it took.

Working Demo: Short video (under 2 min) showing your physical build in action.

Reflection:

  • What surprised you? Describe a moment where the result didn't match your expectation and how that changed your approach.
  • When did you get stuck, and what did you try before it clicked?
  • What would you do differently if you started over tomorrow?
