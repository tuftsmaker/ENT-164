Prepared for ENT-164 · Fall 2026 Class 10 · Device to Cloud

This tutorial builds the class 10 weather station at your own pace. You will wire one sensor, serve its reading from the board, put an app on the internet, give that app a database, and end with a page you can open from anywhere. Each step says what to do and what you should see before you continue.

What you'll build

A DHT22 sensor on your ESP32 reads temperature and humidity. The board serves that reading at its own address, then posts it to an app you deploy on Vercel. The app stores the readings in a Postgres database and shows them on a page. Later you add a weather API, so the page shows both your room and the next few days.

Work in order. Every step depends on the one before it. If something breaks, you know it is the step you are in, not the five before it.
1

Wire the DHT22

Put the ESP32 and the sensor on the breadboard. Four wires, and one resistor if you have the bare sensor rather than the module.

DHT22ESP32
VCC3V3
DATAGPIO 4
GNDGND
10 kΩ between VCC and DATA

Two things that bite. Use 3.3 V, not 5 V: the ESP32 pins are not 5 V tolerant. And leave two seconds between reads, or the sensor returns stale numbers and then errors.

Different pin? Any free GPIO works. If you use another one, say which when you talk to opencode: "the DHT22 data pin is on GPIO 15". Nothing else changes.
The module versus the bare sensor. The three-pin module has the pull-up resistor built in. The bare four-pin sensor needs the 10 kΩ between VCC and DATA, or the data line floats and every reading fails.
2

Register the board with Tufts IT

Tufts Wi-Fi expects every device to sign in through a web page. Your board has no browser, so IT registers its MAC address by hand.

Plug the board into your laptop and ask opencode to print its MAC address. It is six pairs, like 24:6f:28:1a:2b:3c.

Open access.tufts.edu/manual-non-browser-device-registration on your laptop. Paste the address, give the device your name, and submit. It can take a few minutes to take effect.

Until it is registered, the board cannot join the network, and nothing later in this tutorial will work.
3

Serve the reading from the board

Now ask opencode for the device's own API. Start a session in an empty folder and paste this:

The prompt

I have an ESP32 with MicroPython and a DHT22 sensor. I want to read the current temperature and humidity via an API on the device. Connect the ESP32 to the open Tufts_Wireless network. Serve it at GET /device/readings.

Run what it writes. When it starts, it prints an address like 192.168.1.42. Open http://192.168.1.42/device/readings in a browser on the same Wi-Fi.

You should see a JSON line with a temperature and a humidity, refreshing each time you reload. That is the sensor, the Wi-Fi and the server all working at once.

If the browser cannot connect, check the three in order: the board printed an address (Wi-Fi), your laptop is on the same network, and the path is exactly /device/readings. A 404 means the first two worked and the path is wrong.
4

Make a Vercel account

Go to vercel.com and sign up. Choose the Hobby plan; it is the free one and it is enough for this project.

You do not need a credit card, and you do not need to install anything.

5

Make a GitHub account

GitHub is where the code lives. Vercel deploys whatever is in the repository, so the repository comes first.

On Vercel's Import Git Repository panel, click GitHub. It opens GitHub's sign-up: an email, a username, your country, then Create account. Click the link GitHub emails you.

Remember the username. It appears in the repository address and in Vercel's list of repositories.

6

Install the GitHub app and make the repository

Back in Vercel, the panel says it wants the GitHub application installed. Press Install, choose your account, and let it see the repositories you need. All of them is simpler.

Now go to github.com, click + in the top right, then New repository. Name it weather and leave it empty: no README, no .gitignore, no licence. Your agent fills it in.

Press Create repository. On the page that follows, copy the HTTPS address under Quick setup, the one that ends in .git.

7

Let opencode build the app

Start a new opencode session, and paste this with your own repository address:

The prompt

Check out this repository: https://github.com/your-username/weather.git and add a vercel app to show the current temperature and humidity. Push to main when done.

You should see opencode clone the repository, write the app into it, and push to main. Ask it to confirm the push worked before you move on.

New session, not the old one. The device API session is about the board. A fresh session keeps the app work and the board work from tangling.
8

Import the repository and deploy

In Vercel, open Projects and press Import. Pick weather from the list.

On the New Project screen, check that it is importing your repository on the main branch. Leave the root directory and the preset alone: Vercel reads your files and decides. Then press Deploy.

You should see a build log, then a confirmation with an address. That address is your site.

9

Open your site

On the project page, copy the address under Domains, not the one under Deployment. The deployment address changes on every push; the domain stays.

Paste it into a browser. You should see the app's page. It may be empty of readings for now, because nothing is posting yet.

10

Add the database

In Vercel, open Storage, then Create Database, then pick Neon. The free plan is enough.

Vercel makes a Neon project and adds its connection string to your project's environment variables, so the app can already reach it.

What Neon is. It is Postgres, the same database language the deck shows. You never open a SQL console: the app creates its own tables on the first request.
11

Tell opencode about the database

Back in your opencode session:

The prompt

I've added a Neon database to my project to store temperature and humidity readings from my ESP32. POST the temperature and humidity every 5 second to an API endpoint and show the latest values on my weather dashboard.

You should see a table for the readings, a route that accepts them, and a page that shows the latest values. Ask opencode to commit and push when you are happy, and Vercel rebuilds the site on its own.

12

Point the board at the site

Now the board has somewhere to post. In the device session, ask opencode to send the reading to your app every five seconds:

The prompt

Change the program so the board posts its temperature and humidity every five seconds to https://your-app.vercel.app/cloud/history as JSON, and prints the status code and the reply. Keep GET /device/readings working.

You should see a reading appear on your site within a few seconds of the board starting, and a new one every five seconds after that.

13

Make it yours

The page works. Now decide what it should look like, one request at a time:

  • Add a table with the temperature history.
  • Show the last 24 hours as a line chart.
  • Add the five-day forecast from Open-Meteo.

After each request, refresh the page and check it. One change at a time is what makes a broken page easy to explain.

The two routes your app needs

Everything on the page is built from these. If a route goes missing, ask opencode for that one by name.

POST /cloud/historythe boardstores one reading and answers with the current threshold
GET /cloud/historythe pagereturns the readings, newest first, with their timestamps
