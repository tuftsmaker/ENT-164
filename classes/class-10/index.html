The shape of the web

Every page you load is three things talking to each other. Learn the parts and the rest of today follows.

client

Browser

It runs on your machine. It asks for a page or some data, then draws whatever comes back.

the answerer

Server

A computer that is always on. It receives the request, works out the answer, and sends it back.

the memory

Database

It holds the rows. The server asks it questions and it answers with data, quickly and in order.

What an API is

An API is a fixed way to ask another computer for something. It is a menu, not a website.

01 · method

GET or POST

GET reads. POST sends something new. Almost everything you need today is GET.

02 · address

The host and path

The service and the endpoint, copied from the API's documentation.

03 · parameters

After the ?

The values that choose what you get, joined with an ampersand.

04 · key

Who is asking

Many APIs want one. It identifies you, and it is billed to you.

Put together, it is one line: https://api.open-meteo.com/v1/forecast?latitude=42.4&longitude=-71.1&current=temperature_2m. Paste it into a browser and the answer appears as JSON.
A key is a password. Keep it out of screenshots, slides, and public repositories. If it leaks, revoke it and make a new one. Free tiers also count requests per minute and per day, so read the limit before you put a call in a loop.

Connecting a device to an API

Your board is the client here. It asks, waits, reads the answer, and does something physical with it.

Step 1

Join the network

  • Connect to Wi-Fi
  • Wait for an address
  • Check it connected before you ask for anything

Step 2

Make the request

  • The address from the docs
  • Your parameters
  • Your key, in the URL or a header

Step 3

Read the answer

  • Check the status code first
  • Turn the body into JSON
  • Pull out the one value you need
Try it in class: ask an AI assistant for a weather-triggered light. "My ESP32 is connected to Wi-Fi. Call a weather API for the current temperature in Medford, print it, and turn an RGB LED blue when it is below 10 °C. Check once every ten minutes." Ten minutes, not one second: the weather does not change faster, and free tiers count requests.

Connecting a website to a device

In Class 6 your board served the page. Now the page lives on the internet, and the board is the thing it controls.

Class 6

The device serves the page

The board runs a web server and your phone joins its Wi-Fi. Nothing else is needed, and it only works on that network.

Today

The site sits in the middle

Board and browser both talk to a website. It works from anywhere, and the site has to hold the last command.

Why the device starts: a board behind a home router has no public address. It can call out, but you cannot call in. So the device asks the site for new commands, every second or so, and the site answers with the last one.

For your final project

The web is free input and free output. Pick one of each.

input

React to the world outside

Weather, transit, a shared sheet, a model. One input that changes what your build does is enough.

output

Be watchable from a phone

A page that shows the state is easier to demo than a serial console, and easier for a visitor to try.

honesty

Design for the day it is down

If the API does not answer, say so on the screen. A fallback is part of the design, not an afterthought.
